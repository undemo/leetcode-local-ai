# 力扣 Leet 原生 API Hook

v2.5.1 直接接入原站 JavaScript，复用 Leet 侧栏、输入框、消息列表、Markdown、代码复制、工作流按钮、新对话和历史面板，以及提交页原有的「分析」按钮、方法卡片、效率卡片、复杂度曲线和代码风格卡片。顶部按钮继续由原站打开和调整侧栏。

## 更新与配置

1. 在油猴中打开旧脚本，将全文替换为 `leetcode-local-ai.user.js`，保存。
2. 完整刷新力扣页面，清除上一版已经运行的浮窗和事件监听。
3. 从油猴菜单设置「Leet · Base URL」「Leet · API Key」「Leet · 模型」。
4. 打开油猴菜单「Leet · 设置」，调整全局思考开关、思考强度和流式输出。
5. 点击原站顶部紫色「问下 Leet」，在原输入框中对话。模型名称旁的思考下拉框可单独覆盖全局设置；原生 Agent 开关用于启用本地工作流快捷操作。
6. 打开自己的提交详情，点击原来的「分析」。生成后重新打开同一提交，会直接读取本地结果；再次点击「分析」会重新调用 API。

更新至 v2.2 后，旧缓存会自动补充支持的复杂度曲线，并将长段落编号换行，不额外调用 API。新生成的分析优先使用短句；如需把旧分析的措辞也改为精简版，可再次点击「分析」。

v2.4 修复流式回答结束后仍显示生成中，以及关闭全局思考后的分析超时。升级后完整刷新页面；已有的超时分析可点击原来的重试图标或「分析」按钮重新生成，不会自动重发请求。

v2.5 修复最新运行结果混入旧提交失败信息。升级后完整刷新页面，再点击一次「运行」，随后直接在原聊天里追问即可，无须清空历史。每条新问题都会收集当时的最新执行结果；重新生成仍使用原问题的快照。

v2.5.1 修复新版网页中 Agent 开关被会员提示拦截的问题：兼容原站用户状态模块由 `38189` 改为 `9481` 的变化，恢复原生 Agent 开关和本地工作流。自定义 API 模式不再显示升级 Plus、立即升级或演示视频提示，开关状态保存在本机。更新后完整刷新页面即可，API 配置和聊天历史保留。

默认 Base URL 是 `https://api.deepseek.com`，模型是 `deepseek-flash`；模型名称参考 [DeepSeek 文档](https://api-docs.deepseek.com/)。Base URL 可包含 `/v1` 或完整的 `/chat/completions`。其他服务需支持 Bearer Key、Chat Completions 和本节所述的思考参数。

「Leet · 切换流式输出」可切换 SSE / 普通 JSON。「Leet · 诊断」显示原生模块是否已经接管。脚本必须在 `document-start` 运行；更新后请完整刷新页面。

## 思考设置与流式输出

「Leet · 设置」中的思考开关和强度是全局默认值，影响提交分析和 Leet 对话。默认开启，强度为「高」。思考强度使用 DeepSeek 支持的 `low / high / max`，关闭时发送 `thinking: {type: "disabled"}`，开启时发送 `thinking: {type: "enabled"}` 和 `reasoning_effort`。[参数说明](https://api-docs.deepseek.com/guides/thinking_mode/)

Leet 输入区模型名称旁使用原站 Select 组件显示独立选项：

| 面板选项 | Leet 对话 | 提交分析 |
| --- | --- | --- |
| 跟随全局 | 使用全局开关与强度 | 使用全局设置 |
| 关闭思考 | 显式关闭 | 使用全局设置 |
| 低 / 高 / 最大 | 显式开启并使用所选强度 | 使用全局设置 |

覆盖设置保存在本机，适用于之后的 Leet 对话、追问、重新生成和快捷工作流；选择「跟随全局」即可取消覆盖。设置变化会同步到其他已打开的力扣页，已经开始的请求继续使用发起时的参数。设置不会自动重新生成已有分析或消息。

v2.3 改为用 `GM_xmlhttpRequest` 的 `responseType: "stream"` 读取 `ReadableStream`，逐块解码 UTF-8 和 SSE，并立即交给原生思考/正文渲染。停止会同时取消响应流与请求；另外增加了独立的超时计时器。旧版的 `anonymous: true` 会让 Chrome 油猴使用 fetch，而部分版本不会在文本进度回调中持续提供正文，导致最后一次性显示。[油猴文档](https://www.tampermonkey.net/documentation.php?q=GM_xmlhttpRequest)

v2.4 收到 SSE 的 `finish_reason` 或 `[DONE]` 后立即完成任务，清除超时计时器并取消底层读取，不再等待连接 EOF。完整的 Chat Completions JSON 响应也能直接结束。聊天由原生完成事件恢复发送按钮；提交分析立即校验并保存结果。提前断开且没有完成标记的 SSE 仍按中断处理，不会把不完整回答误判为成功。

服务返回普通 JSON 时仍可显示完整结果；服务或中转如果缓冲了整个响应，脚本无法提前显示尚未收到的文本。提交页的原生分析卡片仍在结构化 JSON 完整并通过校验后展示。

## 运行与提交上下文

原站 `70403.getAllVariables()` 先合并运行结果，再合并可见提交详情。后一步会覆盖 `failed_testcase`，同时留下新运行的 `code_answer` 等数组，形成“输入和输出来自新运行，失败用例却来自旧提交”的矛盾。v2.5 从原生执行状态收集结果，不再把这些字段混为同一份判题数据。

- 默认优先使用最近一次点击「运行」或「提交」的结果。运行中、网络错误等阶段不会沿用之前的失败或通过结论。
- 运行完成后，将每组输入、实际输出、预期输出、标准输出和原生 `accepted` 判定放在同一行。失败用例从本批结果提取；全部通过后不再附带旧失败用例。自定义判题继续以原生判定为准，不仅比较输出字符串。
- 保存运行开始时的代码与语言、实际执行输入。之后修改编辑器或测试输入时，会区分已运行的版本和未运行的修改。
- 用户明确引用某次提交时，保留该提交并标记来源；默认追问最新运行时不附带旧提交失败字段。
- 每条消息保存自己的上下文快照。历史轮次明确标为当时状态，最新问题以本轮结果为准；重新生成复用原问题快照。切换题目或重置执行状态后清除当前执行记录。

上述记录来自当前页面的原生状态，不会自动执行代码。完整刷新后需重新运行一次以建立新的执行快照。当前适配依赖原站正常的执行顺序；未额外关联底层 `interpret_id`，不保证在运行尚未结束就跨题执行时，能区分原站自身迟到回调造成的结果串扰。

## 提交分析与缓存

原站调用链为 `submissionSubmitAnalysis(submissionId)` → `submissionAnalysis(submissionId)`。前端只发送提交 ID，没有携带分析提示词。已生成结果由服务端查询返回；React Query 另外保存当前页面的查询缓存，分析期间每秒轮询。

脚本保留这条前端调用链，生成操作改为自定义 API，返回原卡片需要的字段：方法、核心思路、思考问题、当前与建议的时间/空间复杂度、效率建议、可读性与结构评分、风格建议。原服务端提示词无法从已检查的前端 JS 还原；脚本使用面向这些字段的中文提示词，因此分析措辞与结论不保证和官方模型完全相同。

- 结果按提交 ID 分别保存在油猴的 `native-leet-analysis:{提交ID}` 中。刷新、关闭后重新打开均可恢复，无须重复请求模型；更换设备或清除脚本数据后不会自动同步。
- 没有本地记录时，仍会只读查询官方已有的分析；如果已完成，会保留下来。点击「分析」后使用自己的 API 生成新结果，不调用官方分析生成或扣减次数的接口。
- 原生点赞、差评分类与文字反馈也保存在本地，不会发送给力扣或模型服务。
- API 错误、无效 JSON 或输出截断会显示原生错误卡片，可点击原来的重试图标。刷新中断的请求不会自动重发。
- 提交代码、题干和该次提交的运行数据会发送给你配置的 API。不会附带力扣 Cookie 或提交者的账号资料。
- 分析不受力扣每日次数约束，仍受自定义服务的余额与额度限制。设置与聊天共用。

原生图表根据 `{complexity, displayName, funcStr}` 在前端绘制函数曲线，参考曲线来自 `allPinnedComplexitys`；不是每次生成一张图片。v2.1 只映射了常见单变量表达式，所以 `O(n*target)` 只有文字。v2.2 仍复用原绘图组件，并支持乘积、求和、幂、对数、平方根、阶乘和变量别名。当前曲线与优化曲线最后绘制，避免被重合的参考线盖住。

原组件只能显示单变量曲线。对 `O(n*target)`，脚本保留真实复杂度，按 `target = n` 绘制等规模示意，并在图下明确标注；不会把实际复杂度改写成 `O(n²)`。时间/空间复杂度继续使用原切换控件。

原生图表通过 `Function(...)` 执行 `funcStr`。脚本忽略模型提供的函数，只从固定公式或受限数学语法生成表达式；不支持的表达式保留文字。

分析提示词要求：总结和核心思路各一句短评，效率建议 2–4 点，风格建议 1–3 点，每点优先使用短句。界面保留换行、增加行距；旧长文按句子拆为编号段落，原始缓存内容不截断、不覆盖。

## 功能与范围

- 对话、流式输出、思考内容、复杂度分析、解释代码、优化建议和逐步提示。
- 复用原生选择引用、编辑消息、重新生成、分支消息、停止生成、复制、会话历史、重命名和删除。
- 模型和工作流由本地适配器提供，在原生控件中显示。原生全局规则和自定义命令保存到油猴存储。
- Key 从油猴菜单配置，保存在油猴存储中；原生设置界面仅使用托管占位值。模型请求通过 `GM_xmlhttpRequest` 直接发往配置的服务，不携带力扣 Cookie。
- 如果使用原生设置中的「验证」，脚本关闭思考并向自定义服务发送一个最多 8 个输出 token 的简短请求，验证成功才保存新 Key；不会发送给力扣。
- 上下文使用原生请求的题目 slug、代码和选中引用，测试结果按最新一次原生执行收集；额外读取已加载题干和需要引用的可见提交代码，补足原服务器原本按 ID 查询的内容。
- 会话保存在本机油猴存储中，支持按题目恢复。原站云端历史不混入本地会话。
- Agent 开关启用本地提示工作流。当前后端是普通模型对话，不实现原服务器的工具执行器、自动运行测试或自动修改编辑器；代码块仍由原站渲染和复制。

目前针对中文站上述构建适配。模块 ID 或原站消息协议变化时需要更新 hook，无法保证未来版本兼容。接口 401 请检查 Key，404 检查 Base URL 与模型，429 稍后重试；网络错误检查代理及油猴对 API 域名的跨域授权。
